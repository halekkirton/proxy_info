# 分批发布计划

## 执行原则

当前准备的是第 1 版，尚未提交、推送或确认线上部署。每次用户说“做第 N 版”，接续助手按本文件修改并检查；是否提交、推送以当次用户授权为准。六版是内容批次，不是固定日期，也不承诺搜索收录效果。

不增加发布开关、定时任务、草稿系统或后台。`site/config.json` 的 `articles` 只列本版需要公开的文章，其余正文仍保存在私有仓库中。保留纸白与墨绿样式，不重做设计，不重写已完成正文，不改变已发布文章 URL。

只删除首页入口还不够：未发布文章不能出现在生成目录、侧栏、前后篇导航和 sitemap 中，也不能残留在 dist。现有构建会在生成前清空已确认位于项目根目录的 dist，避免旧文件混入发布包。

## 每次需要改的地方

1. `site/config.json`：加当版文章对象，保持编号顺序；摘要和 description 沿用基线，不复制 Markdown 正文到配置。
2. `scripts/build.mjs`：更新首页篇数、阶段数、侧栏计数；按本版恢复指定快捷入口。卡片、侧栏、分页及 sitemap 已从配置生成，无需逐页手改。空分组自动不显示。
3. `scripts/check.mjs`：更新文章数、正常页面数和 sitemap 项数三个断言。
4. `scripts/browser-check.mjs`：更新首页卡片数、页面总数日志、无 JS 导航预期与本版末篇跳转；将“未发布文章 404”的检查改为下一篇仍未开放的地址，V6 则删除这条检查。
5. 本文件和 `SESSION_HANDOFF.md`：记录完成版本、实际检查结果、是否已提交推送，不把本地构建写成线上成功。

## 验收与交付

- 跑 `npm run build`、`npm run check`；用真实 Pages 子路径再构建、检查一次 canonical、sitemap 和站内链接。
- 跑 `npm run test:browser`：1440、390、320 宽度，首页卡片、当前全部文章、关于、404、手机目录、无 JS 导航。
- 检查 dist 只有本版文章，直接访问下一篇未发布地址返回 404，没有未发布页面链接或空分组。
- 查看 `git diff --check`，不得提交 dist、node_modules、截图或凭据。
- 拉取、远端查询、推送统一使用单次参数 `-c http.proxy=http://127.0.0.1:7897`，不改全局 Git 代理。未获当次发布授权时只交付本地改动。

第一版完成后，用户下一次只需说“按计划做第二版”，无需重新决定文章顺序或设计页面。
