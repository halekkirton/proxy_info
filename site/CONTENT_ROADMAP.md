# 后续文章路线图

这份提纲用于规划后续科普文章。新文章仍需遵循 `humanize-writing/SKILL.md`：先解释问题，再介绍方案；不虚构实测数据，不把技术可行性写成稳定性或安全性承诺。

## 一、基础概念与选择

1. **机场、VPN、代理和自建服务到底有什么区别**
   - 机场订阅提供了什么
   - 商业 VPN 与代理服务的信任关系
   - 自建服务并不等于匿名或零成本
   - 适合什么人，谁不适合折腾

2. **节点、入口、落地、出口：代理链里的几个地址**
   - 节点和服务器的关系
   - 入口机、落地机、出口 IP 的区别
   - 为什么“有节点”不代表所有应用都能使用

3. **二层代理是什么：从本地代理到上游代理**
   - 什么是代理套代理
   - 本地客户端、上游代理和目标网站的路径
   - 延迟、故障定位和 DNS 泄露问题
   - 什么时候二层代理只是增加复杂度

4. **代理链、级联代理和多跳网络的区别**
   - 术语在不同软件中的含义
   - 多跳带来的隐私收益与性能代价
   - 不要把多跳等同于匿名

## 二、客户端与本地流量接管

5. **Proxifier 是什么：让不支持代理的软件走代理**
   - 系统代理、应用代理和进程级转发
   - 规则优先级、目标地址和端口
   - DNS 处理方式
   - 常见误区：规则写了但程序没有经过 Proxifier

6. **Proxifier 与 Clash、sing-box、VPN 客户端怎么配合**
   - 为什么通常只需要一个流量接管层
   - 重复代理、环路和端口冲突
   - 如何逐层确认流量到底经过了谁

7. **TUN、系统代理和透明代理有什么区别**
   - 覆盖范围
   - UDP、IPv6 和 DNS 的边界
   - 全局、规则和直连模式

8. **Windows、macOS、Linux 的代理设置差异**
   - 系统代理开关不代表所有程序都遵守
   - GUI 应用、终端程序和服务进程的区别
   - 环境变量与应用独立配置

9. **如何判断一个应用到底有没有走代理**
   - 日志、连接测试和出口地址
   - 抓包与最小化验证
   - 只改变一个变量的排查方法

## 三、Clash 与规则进阶

10. **Clash 负载均衡配置方法**
   - 负载均衡解决什么问题
   - url-test、fallback、load-balance 等策略的思路
   - 节点健康检查与实际业务可用性的差别
   - 规则组嵌套、故障转移和切换抖动

11. **Clash 代理组怎么设计：手动、自动测速与故障转移**
   - 代理组的层级
   - 地区组、服务组和最终出口组
   - 避免循环引用和过度复杂化

12. **Clash 规则配置方法：域名、IP、进程和 GEO 数据**
   - DOMAIN、DOMAIN-SUFFIX、IP-CIDR 等规则
   - 规则顺序和最后一条 MATCH
   - 规则集更新失败时的表现

13. **Clash 订阅转换是什么，哪些转换不能盲信**
   - 配置格式转换与节点能力转换
   - 订阅转换服务的隐私风险
   - 转换后如何核对规则、DNS 和传输参数

14. **Clash DNS 配置排查**
   - fake-ip 与 redir-host 的基本区别
   - DNS 泄露、解析失败与分流错误
   - 浏览器 DoH 与客户端 DNS 的冲突

15. **Clash 连接成功但部分网站打不开**
   - 节点可用性、规则命中和目标网站限制
   - IPv6、QUIC、MTU 与证书错误
   - 通过日志缩小问题范围

## 四、自建服务与服务器基础

16. **自建机场之前要先算什么**
   - VPS、带宽、流量、IP 和地区成本
   - 维护时间、封禁风险和故障处理
   - 钱可能白花：买到的 VPS 在自己的网络下连接不佳、IP 无法正常使用、套餐或流量选错
   - 下单前核对退款窗口、退款条件、IP 更换费用和流量计费方式
   - 先小额、短周期验证，再决定是否续费；不承诺测试通过后长期可用
   - 自建服务与商业订阅的取舍
   - 不把“自己搭”写成“天然更安全”

17. **自建 VPN 入门：WireGuard 与 OpenVPN 怎么选**
   - 隧道模型与适用场景
   - 移动端、桌面端和路由器支持
   - 密钥管理、撤销设备和备份

18. **自建代理服务器的最小安全基线**
   - SSH 密钥、最小权限和防火墙
   - 系统更新、日志和时间同步
   - 禁止开放不必要的管理端口
   - 如何发现配置已经暴露

19. **自建机场的入口、落地和面板分别做什么**
   - 控制面与数据面
   - 订阅生成、用户管理和节点管理
   - 面板泄露、弱密码和备份风险

20. **自建服务如何做基础监控**
   - 在线率、延迟、丢包、带宽和磁盘
   - 监控数据不等于用户真实体验
   - 告警阈值与误报

21. **服务器被封、IP 被限速或节点失效怎么办**
   - 先区分服务商、IP、端口和协议问题
   - 备份配置与快速迁移
   - 不要通过不断换端口掩盖根因

22. **自建服务的流量成本和带宽估算**
   - 峰值带宽与月流量不是一回事
   - 多用户并发的粗略估算方法
   - 账单异常与流量滥用

## 五、协议、传输与性能

23. **TCP、UDP、QUIC、TLS、WebSocket、gRPC 分别在哪一层**
   - 传输、加密和承载的分层
   - 为什么不能把它们放成同一类协议比较

24. **MTU、MSS 与代理连接不稳定**
   - 分片、丢包和握手失败
   - 移动网络与隧道环境中的典型表现
   - 如何用小范围测试定位问题

25. **延迟、带宽、丢包和抖动哪个更重要**
   - 网页、视频、游戏、远程桌面的不同需求
   - 机场测速结果如何解读
   - 不用单一指标给服务排名

26. **IPv4、IPv6 与代理软件的兼容问题**
   - 解析优先级
   - IPv6 直连造成的路径差异
   - 双栈环境的排查顺序

27. **为什么测速很快，实际使用却很慢**
   - 测速目标与真实目标不同
   - 高峰期、跨网和出口拥塞
   - TLS、DNS 和页面资源的综合影响

## 六、故障排查与可观测性

28. **代理日志怎么看：从启动、握手到转发**
   - 日志级别
   - 常见错误的含义
   - 脱敏后再提交日志

29. **连接超时、连接被拒绝、TLS 错误的区别**
   - 网络不可达、端口未监听和证书问题
   - 每类错误对应的最小检查项

30. **DNS 污染、DNS 劫持和普通解析失败**
   - 表现差异
   - 客户端 DNS、系统 DNS 和浏览器 DNS
   - 诊断时避免同时修改多个设置

31. **订阅能更新但节点不能用**
   - 订阅服务器与节点服务器不是同一件事
   - 配置过期、凭据失效和服务端变更
   - 如何安全地描述问题给服务商

32. **如何写一份有用的代理故障反馈**
   - 系统、客户端、版本、时间和目标
   - 脱敏日志与复现步骤
   - 不要公开订阅链接、密钥和完整配置

## 七、安全、隐私与运营边界

33. **自建 VPN 也会暴露什么信息**
   - VPS 商、出口网站和 DNS 观察者
   - 服务器日志与本地日志
   - 加密、匿名和不留痕不是一回事

34. **代理服务商应该公开哪些信息**
   - 计费、流量、有效期、设备数和退款规则
   - 日志政策与数据保存期限
   - 故障通知和客服渠道

35. **机场测评应该怎么做才不误导**
   - 测试时间、网络、地区、客户端和节点
   - 记录方法与重复测试
   - 不能从一次测速推导长期稳定性

36. **订阅链接泄露后有什么风险**
   - 访问权限、流量消耗和账户关联
   - 撤销、重置和分发控制
   - 截图、日志和公开仓库的脱敏

37. **代理配置备份与迁移**
   - 哪些字段是秘密
   - 加密备份与设备撤销
   - 换客户端时的兼容检查

38. **网络工具的合法使用与服务条款**
   - 技术教程不等于法律意见
   - 所在地法律、单位网络规则和目标服务条款
   - 不把绕过限制写成普遍适用的权利

## 八、适合作为专题系列的组合

- **自建路线**：VPS 基础 → WireGuard → 安全基线 → 监控 → 成本估算 → 故障迁移。
- **Clash 进阶路线**：客户端与核心 → 规则 → DNS → 代理组 → 负载均衡 → 日志排查。
- **二层代理路线**：系统代理 → Proxifier → 上游代理 → 二层代理 → DNS → 环路与性能。
- **服务选择路线**：订阅与节点 → 测速指标 → 计费规则 → 隐私政策 → 故障反馈 → 风险判断。

## 成文与发布规则

以上是选题池，不一次性生成七十篇短文。先确认具体软件、版本和官方资料，再选择能完整回答的问题写作。内容高度重叠时合并为一篇，避免同一搜索意图对应多个重复页面。

自建机场暂按“个人或获授权团队使用的连接服务”规划；若涉及面向公众运营，需要另行确认管理、隐私、计费和当地合规要求。二层代理先说明术语含义，不默认等同于 OSI 二层网络。所有配置示例成文前须核对对应版本并验证，提纲本身不代表已经实测。

## 自建系列需要讲清楚的花费风险

用户特别关心“钱花了，最后却没用起来”。写自建文章时，把这类成本放在购买建议之前，帮助读者判断是否值得开始；不渲染焦虑，也不把自建一定失败作为推广服务的理由。

- **服务器买了，线路却不合适**：机房所在地、宣传带宽和本地访问体验不是一回事。自己常用网络下的延迟、丢包和高峰期表现，购买前未必能完全验证。
- **IP 不能用，换 IP 还可能收费**：是否支持更换、费用与次数限制以商家条款为准，不能假定买服务器就一定能获得可用出口。
- **年付便宜，试错却贵**：长期套餐降低月均价格，也可能增加退出成本。退款期限、可退范围、手续费和流量扣费需要先确认。
- **部署好了，仍达不到使用目标**：连接成功不保证目标网站、流媒体或工作应用可用，也不保证速度符合预期。
- **基础费用之外还有账单**：额外流量、快照、备份、附加 IP 等可能单独计费；超额后是停机、限速还是继续收费，需要逐项核对。
- **后续可能被封锁**：即使购买时能连接、部署后测试正常，服务器 IP、端口或相关连接后续仍可能受到封锁或限制，导致服务中断。更换 IP 或迁移服务器可能产生额外费用，也不能保证长期恢复可用；原套餐剩余费用未必能退。排查时要区分封锁、服务器故障、配置错误和线路拥塞，不能把所有断连都认定为封锁。
- **迁移意味着重新付费**：服务器或 IP 后续出现问题，可能要重购资源、重新配置，旧套餐剩余时间也未必能退。
- **时间也是成本**：部署、升级和排障投入可能超过预期；不熟悉服务器维护时，应把这部分一起算进选择。

文案用具体条件解释风险，不写“自建一定更便宜”“买了就能用”或“自建都是浪费钱”。不引用未经核实的故障概率、损失金额或个人经历。

## 十二、企业 VPN 与远程办公专题

71. **企业自建 VPN 前先确认哪些需求**：远程办公、内网访问、站点互联、人员规模和维护能力，区分员工接入与公共代理服务。
72. **远程接入 VPN 与站点到站点 VPN 的区别**：连接对象、路由范围、权限边界和故障影响。
73. **企业 WireGuard 部署前的设计清单**：地址规划、路由、密钥分发、设备登记与撤销，核对具体实现的身份管理能力。
74. **OpenVPN 在企业环境中适合什么场景**：客户端兼容、证书体系、认证集成、维护成本。
75. **企业 VPN 如何做账号和设备生命周期管理**：入职、换设备、离职、遗失设备与权限回收。
76. **企业 VPN 与多因素认证如何配合**：认证入口、会话有效期、恢复流程；不同方案能力需逐一核实。
77. **连上 VPN 后，为什么还要做最小权限控制**：按角色限制网段、端口和应用，避免连接成功即获得整个内网访问权。
78. **企业网段冲突怎么处理**：家庭网络与公司网络地址重叠、路由优先级、规划与迁移。
79. **企业 VPN 分流与全隧道怎么选**：带宽、隐私、终端管理、公司访问政策与实际业务需要。
80. **远程办公访问内网 DNS 的常见问题**：分域解析、内部域名、客户端配置与排查。
81. **企业 VPN 的日志、审计与员工隐私**：记录目的、最小必要信息、保存期限、访问权限及当地要求。
82. **企业 VPN 高可用和故障恢复怎么规划**：备用入口、配置备份、恢复演练、恢复目标与成本。
83. **企业 VPN 带宽和并发怎么估算**：文件传输、视频会议、远程桌面与峰值负载，区分估算和实测。
84. **分公司互联前要做哪些网络规划**：地址、路由、防火墙、变更窗口、回滚方案。
85. **企业自建 VPN 与托管方案如何比较**：软件费用、服务器、运维人员、支持服务和退出成本。
86. **VPN、零信任访问与应用网关的边界**：按网络或按应用授权、设备状态、身份验证；不把产品标签当成安全保证。
87. **企业 VPN 上线前的验收清单**：授权访问、拒绝访问、设备撤销、DNS、断线恢复、日志与备份恢复。
88. **企业自建 VPN 的花费与中断风险**：资源采购、许可证、运维投入、线路限制、IP 或端口受限、业务停工及迁移成本；不承诺自建比托管便宜。

## 十三、游戏加速与网络体验专题

89. **游戏加速器和 VPN、普通代理有什么区别**：支持的流量、线路选择、平台适配与使用边界。
90. **游戏卡顿先看延迟、丢包还是抖动**：区分网络问题、帧率下降和服务器负载。
91. **游戏加速器为什么有时越加速越慢**：入口绕路、出口拥塞、目标区服和本地网络，使用前后对照测试。
92. **游戏加速节点怎么选**：运营商、区服、线路稳定性和测试时段，不只看最低延迟。
93. **NAT 类型与联机失败有什么关系**：地址转换、端口映射、平台判断差异；核对具体游戏与主机文档。
94. **UDP、丢包与游戏掉线的关系**：应用容错、链路变化、会话超时，避免泛化不同游戏行为。
95. **电脑、主机和手机游戏加速方式有什么不同**：客户端、路由器与热点方案的覆盖范围。
96. **下载快但游戏延迟高是怎么回事**：吞吐与交互时延、下载节点与游戏服务器的区别。
97. **Wi-Fi、网线和移动网络对游戏的影响**：干扰、信号、拥塞和网络切换，通过同条件测试定位。
98. **游戏加速器测速应该怎么测**：同区服、同时间窗口、重复测试、实际对局表现及样本限制。
99. **自建游戏加速中转是否值得**：区服位置、线路质量、UDP 支持、计费、维护和服务条款；先评估再采购。
100. **游戏加速器与 Clash 同时开怎么排查**：接管范围、路由冲突、DNS 和回退，避免同时修改两套规则。
101. **游戏更新、登录和对局为什么表现不同**：下载服务、认证服务与对局服务器可能采用不同路径。
102. **游戏加速服务购买前看什么**：支持游戏与区服、设备限制、退款、隐私、客服；不承诺降低延迟或避免账号风控。
103. **跨区游戏的账号与平台规则要注意什么**：平台条款、购买地区、账号安全，技术可行不代表获得平台许可。
104. **游戏网络故障如何向客服反馈**：时间、运营商、区服、加速节点、错误码和脱敏日志。

## 多站点规划：主题边界与风险分散

用户计划分几个独立站点承载内容，不将所有主题集中在当前 GitHub 仓库或页面。主要考虑：分散某个站点在 Bing 未被收录、难以被搜索到或搜索表现下降带来的影响。这是风险管理目标，不代表多个账号能保证收录，或一定能够分散搜索引擎的相关风险；各站仍可能共同受到内容质量、平台、账户关联及搜索规则变化影响。

| 站点方向 | 核心受众与内容 | 边界 |
|---|---|---|
| 科学上网入门手册（当前站） | 新手概念、机场订阅、服务选择、基础排查 | 保留入门路径，避免变成所有技术主题的杂合站 |
| 代理客户端与配置站 | Clash、Mihomo、sing-box、Proxifier、二层代理、DNS、开发环境代理 | 以具体软件和配置问题为核心；ltproxy 身份待确认 |
| 自建网络与企业远程访问站 | 个人自建 VPN、服务器基础、企业接入、站点互联、安全与运维 | 个人与企业分栏目，权限、维护与成本讲清楚；篇幅足够后可再拆站 |
| 游戏网络与加速站 | 延迟、丢包、NAT、加速器、区服与联机排查 | 以游戏使用场景为主，不复刻通用代理文章 |

这些是可选站点分组，不要求同时上线四个站。仓库、域名和账号如何分配后续再定。先建立各站内容清单与独立定位，再按精力逐个启动。

- 一篇完整文章确定一个主要发布站点，跨站只做必要摘要和相关参考，不复制全文铺站。
- 重叠主题按读者问题分工，例如当前站解释 VPN 概念，企业站讲授权与运维，游戏站讲游戏流量表现。
- 各站独立维护站点地图、规范链接、Bing 验证与收录状态，记录自己的正式地址和部署方式。
- 只在能帮助读者继续解决问题时跨站链接，不建设批量互链或重复关键词入口。
- 多站可共用构建工具和视觉基础，但标题、描述、正文与导航围绕各站实际主题编写。
- 某站收录或流量异常时先查明原因，不以复制到新账号的方式规避搜索规则或处罚。
