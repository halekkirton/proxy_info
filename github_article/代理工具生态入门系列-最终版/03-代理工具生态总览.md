# 代理工具生态总览：核心、客户端、协议、配置和服务

如果只记住软件名称，越学越乱。Clash、V2Ray、Xray、sing-box、v2rayN、Mihomo 经常同时出现，但它们并不是同一种东西。

先别急着背名称。把客户端、核心、协议、配置和服务这五层分开，再看它们怎么配合，会容易理解得多。

## 第一层：客户端

客户端是用户直接操作的程序。它负责导入配置、切换模式、选择代理组、显示连接状态和查看日志。

Clash Verge Rev、FlClash、v2rayN、v2rayNG 都更接近客户端。它们可能调用不同核心，也可能支持多个核心。

所以，“我使用 v2rayN”描述的是界面和管理程序，不一定说明后台实际运行的是 V2Ray、Xray 还是其他核心。

## 第二层：核心

核心负责实际连接。它解析配置，处理认证、协议、路由和流量转发。

Mihomo、V2Ray、Xray、sing-box 都可以放在核心或核心生态这一层理解。核心之间可能支持不同协议、配置字段和路由能力。

客户端和核心可以分别更新。客户端支持某个核心，也不代表界面能配置该核心的全部功能。有时核心文档里已经存在某个字段，客户端还没有相应选项；这时不能只看核心名称，还要核对客户端版本和配置方式。

## 第三层：协议

协议规定客户端和服务端如何建立连接、认证身份、加密和传输数据。HTTP、SOCKS5、Shadowsocks、VMess、VLESS、Trojan、WireGuard 和 OpenVPN 的定位并不完全相同。

协议不等于客户端，也不等于服务商。看到“支持某协议”，只能说明软件具备某种连接能力，不能直接推断速度、稳定性或隐私水平。

## 第四层：配置

配置把客户端、核心、协议和服务地址组合起来。它可能包含节点、订阅、代理组、规则、DNS 和传输参数。

配置格式和字段会随核心不同而变化。配置能导入，不代表每个字段都生效；显示已连接，也不代表所有应用都走了预期路径。

## 第五层：服务和节点

节点通常指一个可以接收代理连接的远程入口。它不是客户端，也不是协议，而是实际承载连接的服务资源。

节点服务商的稳定性、日志政策、带宽和运营方式，会直接影响体验和隐私。开源客户端并不能替第三方节点服务背书。

## 用一句话串起来

可以这样理解：

> 用户通过客户端，调用某个核心，按照某种协议，读取一份配置，连接到远程服务或节点。

遇到陌生名称时，可以先对照这句话，看看它负责哪一部分。这是角色分工，不是数据包依次经过五个程序的意思；配置是参数集合，不是一台额外的中转服务器。

## 为什么网上教程经常讲乱

很多教程为了省事，把客户端、核心和协议都称为“工具”。于是“安装 V2Ray”“使用 Clash”“导入节点”这些说法，在不同文章里可能指不同东西。

读教程时，先问四个问题：

1. 这是客户端还是核心？
2. 这是协议还是传输方式？
3. 这是配置文件还是远程服务？
4. 这个项目是否仍在维护？

这样再遇到新名称，就能先判断它是换了一个界面、一个核心，还是一套配置，不必每次都从头学起。
